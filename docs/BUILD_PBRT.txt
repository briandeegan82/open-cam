pbrt-v4 in this repo lives at third_party/pbrt-v4 (git submodule of upstream mmp/pbrt-v4).

open-cam patches (recommended build)
------------------------------------
open-cam needs a few C++ additions that upstream pbrt-v4 does not have. They are kept
as patches in third_party/patches/*.patch (never committed into the submodule) and
applied by the build script, which is idempotent and leaves the submodule commit alone:

  git submodule update --init --recursive
  tools/build_pbrt.sh                 # apply patches + CPU build -> third_party/pbrt-v4/build/pbrt
  tools/build_pbrt.sh --apply-only    # only apply the patches (e.g. before a GPU build)
  PBRT_NATIVE=OFF tools/build_pbrt.sh # portable binary (no -march=native), as CI caches

Patches:
- 0001-retroreflective-material.patch: Material "retroreflective" (RetroreflectiveBxDF),
  a Lambertian base plus a retroreflective lobe around the incident direction,
  parameterised by the coefficient of retroreflection R_A (ASTM E808/E810, D4956;
  EN 12899) or road-marking R_L (EN 1436). Parameters: "spectrum reflectance" (diffuse
  base), "spectrum ra" (R_A in cd lx^-1 m^-2 at "float observationangle" [deg] and normal
  entrance), "float lobewidth" [deg] (exponential fall-off with observation angle) and
  "float entranceexponent" (q: R_A ~ (cos b_i cos b_o)^(q/2)). Used by the night/dusk
  highway scenes (tools/highway_night.py, docs/HIGHWAY_SCENES.md).
- 0006-spectral-film-jittered-wavelengths.patch: the spectral film draws its 4 hero
  wavelengths one per stratum of (lambdamax - lambdamin)/4, each jittered independently
  (SampledWavelengths::SampleUniformJittered). Stock pbrt shifts all four by the same
  offset, so buckets one stratum apart got identical paths and per-bucket metrics showed a
  periodic ripple (docs/SFR_SPECTRAL_RIPPLE.md). Same cost and expectation; Film "spectral"
  "bool jitterwavelengths" false restores stock sampling.
- 0008-scene-light-camera-deadlock.patch: fixes an intermittent hang while loading
  scenes whose camera sits in a medium (e.g. the hazy/foggy highway). The camera job waits
  for its medium and meanwhile runs other queued jobs on the same thread; a light job
  picked up there called GetCamera() and waited on the camera job below it on the stack,
  so pbrt spun forever (about 1 run in 100 of the dusk-fog probe in
  tests/test_pbrt_e2e.py, and the 3 h 45 min CI stall). Light jobs now take the camera
  transform straight from the camera entity. Rendered output is unchanged.
- 0016-diffuse-area-light-angular.patch: "string angularfilename" on a "diffuse" area light
  names a square equal-area map ("Y" channel, directions in the light's object space, as
  the goniometric light without its y/z swap) that multiplies the emitted radiance along
  each direction, so an emitter can have a beam shape. Each file is loaded once and shared
  by all the lights of a mesh. Values must be <= 1 (light bounds assume a cosine emitter).
- 0020-dielectric-passthrough.patch: "bool passthrough" on a "dielectric" material, as patch
  0017 does for "thindielectric": in the volpath integrator shadow rays pass the surface with
  the single-interface transmittance 1 - Fr(cos theta), and a path hitting it reflects with
  probability Fr or otherwise continues unrefracted. Used for the cabin cornea so that the LED
  lights the retina and iris (build_cabin_scene.py --retina on).
  Used by the rear lamps (--rear-lamp-beam shaped; docs/HIGHWAY_SCENES.md).
- 0026-spectral-film-splat-units.patch: SpectralFilm::AddSplat stores splats in the units of
  AddSample (bucket mean x CIE_Y_integral instead of L / pdf / N, which was the bucket integral),
  and GetImage writes splats in pixels that got no camera sample. Without it the spectral
  buckets of lightpath and MLT were all 0 and BDPT's light-traced share was too dim (bucket
  sum 0.68x the path tracer on a diffuse test scene); tests/test_pbrt_spectral_splat_units.py.
- 0030-wavefront-cpu-only-feature-warnings.patch: under --wavefront/--gpu, pbrt warns when a
  scene uses a patch feature that only the CPU integrators implement, and stops on the caustic
  split (see "Wavefront / GPU: CPU-only patch features" below).
- 0031-guided-path-integrator-openpgl.patch: Integrator "guidedpath", the path tracer with
  Intel Open PGL path guiding (docs/PATH_GUIDING.md). Optional: CMake enables it only when
  Open PGL is found; PBRT_OPENPGL=1 tools/build_pbrt.sh fetches and builds Open PGL v0.7.1
  (tools/fetch_openpgl.sh, needs TBB) first. Without it the integrator name is an error.
  Also adds ImageTileIntegrator::WaveFinished(), a no-op hook for every other integrator.
- 0032-light-bvh-pmf-zero-not-nan.patch: BVHLightSampler::PMF returns 0 for a light whose bounds
  give it zero importance from the shading point; stock pbrt divided 0 by 0 and returned NaN
  (seen for tail lamps facing away from the road point), which a MIS weight then turned into a
  NaN sample that pbrt sets to black.
- pbrt-v4-spectral-basis-infinite-light.patch: an "infinite" light may give both
  "filename" and n "L" spectra; the equal-area image then has channels B0..B{n-1}, each
  a per-pixel luminance weight of the corresponding (unit-luminance-normalised) spectrum,
  so Le(w) = scale * sum_k B_k(w) L_k(lambda). "float illuminance" still sets the
  upper-hemisphere illuminance. Used by the spectral highway sky (--sky hosek,
  --sky-spectrum daylight; docs/HIGHWAY_SCENES.md). RGB maps are unaffected.

To work on a patch: edit the sources in third_party/pbrt-v4, rebuild, then refresh the
patch with `git -C third_party/pbrt-v4 diff > third_party/patches/<name>.patch` and
restore the submodule (`git -C third_party/pbrt-v4 checkout .`). CI caches the binary
under a key containing the submodule SHA and the hash of the patches + build script.

Without the patches pbrt still builds, but scenes using the retroreflective material
fail to parse (the highway builder only emits it for --time-of-day dusk/night, or
--retroreflective on), as do spectral-sky scenes.

CPU-only build (no NVIDIA OptiX SDK)
------------------------------------
If PBRT_OPTIX_PATH is set in your environment but OptiX headers are missing, the
CMake step enables GPU targets and the build fails. Unset it for a CPU build:

  cd third_party/pbrt-v4
  git submodule update --init --recursive
  env -u PBRT_OPTIX_PATH cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
  cmake --build build -j$(nproc)

The pbrt executable is: third_party/pbrt-v4/build/pbrt

GPU build
---------
Install the OptiX SDK and point CMake at it:

  export PBRT_OPTIX_PATH=/path/to/optix
  cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
  cmake --build build -j$(nproc)

Spectral / color options (scene file)
-------------------------------------
- Piecewise-linear spectra use wavelengths in nanometers; pbrt clips to the
  active spectral range (defaults: lambdamin 360, lambdamax 830; see Option
  directive in the file format docs).
- RGB parameters are interpreted in the current ColorSpace ("srgb" default);
  use ColorSpace before Film if you need another working space for RGB textures.
- Multispectral output: use Film "spectral" (OpenEXR only). The scene generator
  supports `--film spectral` plus `--spectral-nbuckets` and lambda min/max;
  see tools/build_colorchecker_scene.py and README.md.

Project usage notes
-------------------
- Scene input to pbrt is scenes/generated/colorchecker.pbrt (not .exr).
- Build scene files with:
    venv/bin/python tools/build_colorchecker_scene.py
- Render with:
    third_party/pbrt-v4/build/pbrt scenes/generated/colorchecker.pbrt
- Apply EMVA post-processing with:
    venv/bin/python tools/apply_emva_noise.py

Pipeline GPU toggle
-------------------
`tools/run_pipeline.py` can add wavefront mode automatically from pipeline YAML:

  render:
    gpu_enabled: true
    pbrt_args: ["--stats"]

When `gpu_enabled` is true, the pipeline injects `--wavefront` into the pbrt
command unless it is already present in `render.pbrt_args`.

Wavefront / GPU: CPU-only patch features
----------------------------------------
The wavefront integrator (--wavefront, --gpu) is a separate code path. These patch features
live only in the CPU integrators; patch 0030 reports them instead of dropping them silently:
- 0002 "fluorescent" re-emission: warning (the material renders without fluorescence).
- 0017/0020 "bool passthrough" dielectrics: warning (rendered as ordinary dielectrics).
- 0021 "skipcaustics"/"causticsonly": error (summing the two passes would count the caustic
  twice; tools/combine_caustics.py also refuses --gpu/--wavefront on a split scene).
- 0023 per-pixel rotated wavelengths (the spectral-film default): warning; wavefront falls back
  to per-sample jitter (unbiased, noisier buckets). "string wavelengthjitter" "sample" on the
  film silences it.
- 0009 spectral SPPM: wavefront always runs volpath and already warns that "sppm" is ignored.
Not tested on a GPU (no CUDA on the dev VM): the PBRT_CPU_GPU code of 0006/0012 (film) and
0022/0024 (light sampling). --wavefront on a CPU-only build runs but is much slower than the
CPU integrator, so it is only useful for checks.

Build flags (measured on an 8-core VM, GCC 11.4, -O3 -DNDEBUG, wall seconds)
------------------------------------------------------------------------------
- PBRT_NATIVE=ON (-march=native, the local default of tools/build_pbrt.sh): night lead-car
  crop, 64 spp, 2 alternating repeats: portable 11.36 / 11.35 s vs native 10.67 / 10.67 s
  (-6 % wall, -7.5 % CPU; FMA in the goniometric direction maths). Day crop (0.25-0.75),
  32 spp, 3 alternating repeats: portable 9.56 / 9.53 / 9.43 s vs native 9.39 / 8.98 /
  10.89 s, i.e. no gain within the +-3 % run-to-run spread.
- -march=x86-64-v3 (10.05 / 9.11 / 9.89 s) and LTO (9.81 / 9.72 / 9.91 s) on the same day
  crop: within +-3 % of portable; not worth a variant.
- CI builds with PBRT_NATIVE=OFF so the cached binary runs on any runner.
- PGO: not measured (ESTIMATE 5-10 %; needs a two-stage build that the cached CI binary
  cannot use).
